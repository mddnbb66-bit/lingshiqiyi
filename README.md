# GloBal-Text：《搅动泥沙》说明主线

这个分支只放说明文件（md，外加 `docs/` 下的设计文档），不放游戏代码。规则沿用《拆·铁》游戏 demo 的 git 规范。

## 文件
- `X.md`（A.md … Z.md）：各号的工作记录。
- `docs/`：设计文档与参考资料。

## 分支
- `main`：全局主线，当前版本以 `git log origin/main -1` 为准。
- 各号只在自己字母开头的分支写代码（如 I 号：`I-web`）；其他字母的分支只读不写。
- 自己负责的分支不存在时：先问用户，确认后从最新 main 新建；第一次推送用 `<分支名>-<最新 main 版本号>`，之后每次 +1。
- **用词**：「合并」= 支线 → main（必须用户拍板）；「拉取」= main → 自己的支线（开工前照做，不用另问）。有冲突先问用户，不要自己强解。

## 版本
- 代码分支版本格式 `<分支名>-x.x.xx`，每次推送 +1，各分支各自计数。
- **每次版本号 +1 之前都要先明确问用户，用户确认后才推。**
- 游戏内版本串（`work/shell.html` 的 `<title>` 和标题页右下角版本号）同步改成同一个版本。
- main 的 commit 标题 / 版本：`main-x.x.xx-from <来源分支版本>`，main 自身版本每次 +1。合并前再 `git fetch`，用 `git log origin/main -1` 定号；推送被拒就重新 fetch、重新定号，并告诉用户。

## commit
- 代码分支：标题 `<分支名>-<新版本>：<一句话摘要>`，正文逐条写改了什么、动了哪些文件、怎么验证。
- 改了 `work/` 源码就要运行 `python3 work/build.py` 重新生成 `index.html`、`game.js`、`three.classic.js`，不能只改产物。
- 代码规范：现代 JavaScript，不用 `var`；默认 `const`，需要重新赋值才用 `let`；class、箭头函数、解构、可选链。

## GloBal-Text 记录
- 只能改自己的 `X.md`；`docs/` 只有用户让更新时才动。
- 每次推完代码分支（或合并到 main），马上在 `X.md` 追加一条：时间（UTC+8）、哪个号、推到哪个分支哪个版本、做了什么、还有什么没做完。
- 推了代码时，commit 标题 `Text from <刚推的分支版本>`，版本完全一致。
- 只改说明、没推新代码时：标题 `Text from <自己分支当前版本>（仅文档）`。

## 设计文档
- 现行版本：**v1**（2026-11-27），`docs/搅动泥沙_设计文档_v1.md`。做玩法改动必须对照文档；文档和代码对不上先问用户。
- 文档以后更新：新版放进 `docs/`，改这一节的「现行版本」，旧版保留不删。

## 开工前必读
1. `git fetch`，读本 README（以最新版为准）。
2. 读最近一次更新的 `X.md`：`git log origin/GloBal-Text -1 --name-only --format= -- '[A-Z].md'`，再读自己的 `X.md`。
3. 读设计文档现行版。
4. 新对话不依赖旧对话的记忆，一切以本分支和仓库现状为准。

## 换对话交接
- 同一个号同时只留一个对话在干活。
- 旧对话：不再开新活；没推的改动先问用户是升版推送还是放弃；在 `X.md` 追加「交接」（当前分支和版本、没做完的事、待确认的事、踩过的坑），commit 标题 `Text from <当前分支版本>（交接）`；写完就停手。
- 新对话：读最近一条「交接」及之后的记录，用 `git log origin/<自己分支> -1` 核对版本，对不上先问用户。
- 干活中途很久没推送时，每告一段落记一条「仅文档」进度。
